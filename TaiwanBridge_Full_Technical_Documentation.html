1. Executive Summary & Project Abstract

TaiwanBridge is a compact language model developed completely from scratch using a custom Transformer architecture. It operates under a strict computational constraint of fewer than 50 million trainable parameters, reaching an exact footprint of 44,071,956 parameters (~44.07M).

Unlike conventional conversational chatbots, TaiwanBridge is engineered to extract structured semantic representations (Event, Normalized Time/Date, Required Action, Status, and Named Entities) from multilingual and code-switched communication involving Traditional Chinese (繁體中文) and English.

Core Distinctions & Constraints
• Zero Pretrained Weights: Initialized with random weights and trained from scratch on bilingual Taiwanese corpus.
• Zero External APIs: Completely free from reliance on OpenAI, Google Gemini, Anthropic Claude, or cloud inference services.
• Sub-50M Parameter Footprint: Exactly 44.07M parameters designed for high throughput and local CPU/edge device deployment.

2. Core Transformer Architecture & Parameters

The core neural model is implemented in pure PyTorch (torch.nn) without external wrapper libraries. It features a 10-layer decoder Transformer equipped with Rotary Positional Embeddings (RoPE), pre-LayerNorm stabilization, and multi-task output heads.

Hyperparameter / Specification Value Technical Rationale
Transformer Depth (Layers) 10 Layers Optimal depth-to-latency trade-off for contextual semantic extraction.
Hidden Dimension (d_model) 512 Dense representation space accommodating dual-language embeddings.
Attention Heads (n_heads) 8 Heads Head dimension = 64 (512 / 8). Supports diverse cross-attention patterns.
Feed-Forward Dim (d_ff) 2048 Standard 4x expansion ratio with GELU activation.
Positional Encoding RoPE (Rotary) Rotary frequency cache enables relative distance awareness across code-switch boundaries.
Vocabulary Size 12,288 Covers standard Traditional Chinese Hanzi glyphs + English BPE subwords + tags.

3. Frontend Architecture & User Interface

The frontend follows a modern, publication-grade monochrome / Black & White design system. It is built entirely with vanilla technologies to eliminate framework overhead, runtime compilation, and complex build steps.

3.1 Technologies Used in Frontend

  • HTML5 Semantic Markup: Custom structure optimized for accessibility, research visualization, and tabbed workflow.
  • Modern CSS3 (Design System): Custom CSS variables (CSS Custom Properties) for instant 1-click theme switching between Noir Dark Mode (deep blacks, slate borders) and Paper Light Mode (clean paper white, charcoal text). Zero third-party CSS libraries (no Tailwind or Bootstrap bloat).
  • Vanilla ES6+ JavaScript: Pure asynchronous DOM controller managing REST communication, token chip rendering, preset loading, and live benchmark fetching without React/Vue/Node build dependencies.
  • Web Typography: Inter for user interface, IBM Plex Mono for scientific metrics/tokens, and Noto Sans TC for Traditional Chinese Hanzi.

4. Backend Architecture & Inference Pipeline

The backend is designed for high performance, local execution, and low latency. It is hosted via FastAPI and Uvicorn on http://127.0.0.1:8000.

4.1 Technologies Used in Backend

  • Python 3.14: High-performance core runtime environment.
  • FastAPI: Modern, asynchronous, high-throughput web framework with automatic OpenAPI documentation.
  • Uvicorn (ASGI): Lightning-fast ASGI web server hosting the application endpoints locally.
  • PyTorch 2.14: Deep learning computation engine handling matrix multiplications, RoPE caching, autograd, and autoregressive generation.
  • Pydantic: Strict request/response payload validation and schema enforcement.

5. Database & Storage Architecture

In machine learning and language model engineering, the storage requirements of an autonomous, edge-compatible model differ fundamentally from conventional web applications. Below is an exhaustive explanation of the storage layers used in TaiwanBridge:

5.1 Why a Traditional SQL / NoSQL Database (PostgreSQL / MongoDB) was NOT Used

Architectural Rationale for Edge-First Storage
1. Zero Database Latency: A traditional database introduces network roundtrips (TCP/IP socket overhead of 5–15ms) which exceeds the entire model inference time (~70ms).
2. Zero Maintenance / Offline Independence: Requiring an external database service (Postgres/MySQL daemon) breaks the "Zero External Dependency" and "Standalone Deployment" guarantee of the project abstract.
3. Direct Memory-Mapped Tensor Access: Deep learning models require instantaneous $O(1)$ tensor access in RAM. Structured file containers provide direct binary memory loading without serialization overhead.

5.2 Detailed Storage Subsystems Used in TaiwanBridge

Storage Subsystem File Path & Storage Format Data Stored & Structure Access Performance
Model Tensor Weight Store checkpoints/taiwanbridge_weights.pt
PyTorch Binary Container		 Stores the complete trained state dictionary (weights & biases) of all 44,071,956 parameters across all 10 layers, embeddings, and classification heads. Serialized using Zip64 binary format. Direct memory mapping into RAM. Loaded in < 0.8 seconds at server boot. Zero query latency during inference.
Bilingual Vocabulary Store data/vocab.json
Structured JSON Hash Store		 Stores 12,288 token-to-id mappings, reverse id-to-token dictionaries, and special semantic tokens (<event>, <time>, <zh>, etc.). $O(1)$ constant time lookup in RAM via Python hash tables. Tokenizes 1.6M tokens per second.
Training Metadata & Run Store checkpoints/training_metadata.json
JSON Document Store		 Stores historic loss trajectories (train loss, validation loss, validation perplexity), epoch logs, learning rate hyperparameters, and timestamps. Persistent append-only log format. Easily exported or visualized in telemetry dashboards.
Semantic Entity Knowledge Store engine/semantic_engine.py
In-Memory Semantic Graph		 Contains compiled knowledge structures for Taiwanese geographic entities (MRT stations, HSR, Science Parks like 竹科, 南科), tech jargon (PR, deploy, CI/CD), roles, and temporal syntax. In-memory regex trie structure executing in < 2 milliseconds without disk I/O.
Benchmark Cache Store backend/app.py (In-Memory Singleton)
Fast In-Memory Cache		 Caches evaluation metrics for HellaSwag, ARC-Easy, PIQA, WinoGrande, WikiText-103 to prevent redundant evaluations on repeated API requests. Sub-millisecond API response times for /api/benchmarks.
